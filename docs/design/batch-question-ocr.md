# 批量题目 OCR

本增量以 Phone04 的冻结交接副本为基线。保留原单题拍照、裁剪和手动录题，新增“单张大图”和“多图识别”入口。识别结果都是待校对草稿，只有用户编辑、勾选并确认后才调用既有题库创建接口。

## 输入与来源

- 每批 1–4 张 PNG/JPEG；每张最多 16 MiB、1600 万像素、最长边 16000 像素，整批最多 32 MiB。
- 先校验压缩字节和实际图像格式、尺寸，再逐图解码。Phone 原样保留自己的临时原图副本，不删除图库文件。
- 选择顺序对应 `image-0`、`image-1` 等来源。服务端返回原图尺寸、切片整数矩形、片段原文及每题的来源引用。
- 基础切片带 256 像素重叠，按来源及从上到下、从左到右的顺序识别。基础切片最多 16 个，含补识别整批最多 24 个。

## OCR 与重组

切片调用现有 OCR 配置，重组调用现有 tutoring 配置。每张原图独立拆题，不跨原图合并或去重；重组仅做同图顺序整理、跨片拼接、去重和题目拆分，固定 JSON 协议明确禁止推测缺字、补条件、解题或补答案。OCR 文字、来源和模型返回的位置资料都作为不可信数据校验。结构和引用校验不能证明模型文字的语义完全忠实，人工校对仍是必需步骤。

重组模型只能以已知切片 ID 和内部边缘枚举标记疑似截断。服务端验证来源与边缘，计算移动后的切片区域，再补识别。最多一轮补识别、每图最多两个补片、最多两次重组；仍无法可靠拼合的题目和未覆盖片段标为待人工核对。没有无限重试或整批重跑。

## 请求与恢复

| 操作 | 接口 | 行为 |
| --- | --- | --- |
| 开始 | `POST /api/v1/learning/ocr/batches/{requestId}` | multipart `image0` … `image3`；同账号、同 UUID、同内容只返回原批次，不重复执行；同 ID 不同内容冲突 |
| 查询 | `GET /api/v1/learning/ocr/batches/{requestId}` | 只查询，不调用模型；用于轮询和提交响应未知后的恢复 |
| 取消 | `DELETE /api/v1/learning/ocr/batches/{requestId}` | 禁止后续步骤，保留已产生片段；已发出的供应商调用可能仍在结束中 |

成功响应统一为 HTTP 200，包含 `requestId`、`status`、`stage`、`completedTiles`、`totalTiles`，以及可选的 `result`、`errorCode`、`message`。所有持久读写按认证账号隔离。multipart 名称、声明格式及大小在请求阶段校验；实际图像完整解码在单个 worker 内校验，不合法时批次变为 `FAILED`。

| 状态 | 含义 |
| --- | --- |
| `QUEUED` / `RUNNING` | 等待 / 处理中 |
| `COMPLETED` | 已生成可校对题目，仍须人工确认 |
| `INCOMPLETE` | 有缺失、接缝或覆盖疑问，必须人工核对 |
| `EMPTY` | 已完成处理但没有识别到题目 |
| `FAILED` | 处理失败，保留已有片段与客户端原图 |
| `CANCELLED` | 已取消，后到结果不能覆盖取消状态 |
| `UNKNOWN` | 服务端执行租约过期，不能确认完成；不自动重跑 |

Phone 的网络响应未知单独显示，不把连接失败变成空结果。提交结果未知后只查询原 UUID；新一次识别必须由用户明确发起。明确未受理恢复仅限初次 POST 返回 `409/A0455`（同账号另有活动批次）或 `429/A0502`（本地输入槽或全局识别队列已满），两者均在建立本批次前拒绝：保留原请求 ID 与原图，恢复手动“开始本批识别”，不会自动重发。`409/A0445`、网络未知、泛 `503` 及查询 `404` 均不按未受理处理。服务端最多一个执行、一个等待批次，单账号最多一个活动批次；应用不持久化原图，multipart 临时文件由容器按请求生命周期清理，worker 只持有有界内存输入。图片不写数据库或日志。服务重启不会自动续跑模型，五分钟执行租约过期后返回 `UNKNOWN`；持久身份用于阻止重复调用和查回已有片段。

## 校对与入库

运行阶段不覆盖人工草稿；终态结果导入后，每题都有独立文本、预览、选择状态和确认请求 ID。批量确认沿用现有 `ManualQuestionInput` 幂等语义。提交响应未知时冻结原确认内容，查询式重试使用同一请求；不得修改内容后换 ID 直接重发。

失败或不完整结果即使没有拆出题目，也可展开原片并“从此图手动补题”，无需再次调用模型。服务端 `UNKNOWN` 携带的片段可以继续校对；客户端仅网络响应未知时保留原请求，等待查询恢复。

退出录题页面保留当前登录会话内的草稿和原图；账号切换清理旧账号的自有材料。已保存题目不会重复提交。只有 `COMPLETED` 且某张来源图关联的题目都已确认，才自动清理该图；不完整、失败、取消或未知批次的原图保留至用户明确丢弃。应用进程结束后的草稿恢复不作保证。

## 集成边界

新增迁移使用 `V2026102605__batch_question_ocr.sql`。未更改冻结基线的 conversation-context 迁移；与 develop 的迁移顺序由集成方统一处理。未修改 PhoneTutorV2Page、多 Agent 角色/运行协议、presence、顶部标题栏或底部 Tab 的既有结构。

本轮包含 fake 模型的小样本、必要服务端构建、ArkTS 编译，以及用户单独授权的一张真实题图（1 次 OCR + 1 次 tutor）。真实样本拆出 12 道大题，但有一处 OCR 公式误读需人工修正；原图只规划一片，尚未验证真实跨片拼接。未使用旧 rc7 预算，不代表 P6 正式通过。设备多选和校对交互仍未验证。


## Phone 题卡与界面技能应用（2026-10-26）

设计对象是手机上校对整道大题的学习者，单一任务是核对后选择添加；采用“编号习题纸”的窄侧线、原题号和两行摘要组织卡片，避免同时铺开所有编辑器。保留 PhoneTheme 的蓝色 `#246BFF`、深蓝 `#123E8C`、正文 `#152744`、辅助 `#5A6B85`、浅蓝 `#E8F0FF` 与白色 `#FFFFFF`；系统字体分别承担 17sp 加粗题号、15sp 编辑正文、11–13sp 来源与状态角色，不改顶部栏或底部 Tab。

每个后端大题对应一张默认折叠题卡，题号从正文开头读取，无法可靠识别时明确使用“题序”；小问不在前端拆分。展开状态独立保存，稳定 itemId 和原生 `@Observed` / `@ObjectLink` 保留编辑器身份；Markdown 预览使用既有 `autoHeight` 适应卡片高度。编辑正文或学科会取消勾选。全选只选择正文有效且未保存、没有未知确认请求的草稿，界面明确全选表示已检查，添加动作只处理已选项，不增加确认弹窗。

准备原图、上传、等待、识别、整理和接缝补识别均使用原生 `LoadingProgress` 与中文阶段文案，分片数只显示真实计数，不换算虚构百分比；错误贴近题卡，折叠时仍可见。新增操作触控高度至少 44vp，主操作 48vp；展开按钮、题号 checkbox、编辑器和原图提供 `accessibilityText`，两行摘要及来源信息处理长文本。只使用有任务意义的系统加载反馈，没有新增装饰动画。

网页专属的 DOM / ARIA、URL 查询参数、CSS 焦点选择器、浏览器 hydration、字体 preload / CDN preconnect 等不直接套用到 ArkUI；本轮以原生 Button / Checkbox、辅助文本、系统焦点与既有安全区和键盘结构落实等价行为。代码与少量状态校验不能替代设备上读屏、键盘光标和长图滚动验收。

原图校对使用独立查看层，复用已有作答查看器的纯几何，支持适合宽度、放大/缩小、倍率显示、横纵拖动与方向按钮；始终读取原缓存，不触发网络或 OCR。顶部和设备返回先关闭查看层，草稿与勾选保持；图片加载有 spinner、失败提示和本地重载。暂离或账号切换会关闭查看层，避免旧账号原图继续显示。
